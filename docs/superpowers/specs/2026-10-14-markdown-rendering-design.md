# Markdown 渲染 —— 设计文档

日期：2026-10-14
状态：待用户审阅
分支：`feat/markdown-rendering`（从 `feat/boss-key` 切出，理由见第 16 节）

## 1. 目标

导入的 `.md` 工作文档现在按纯文本显示，正文里的 `#`、`**`、`|` 原样露在屏幕上，看起来不像一份真文档。本功能把它渲染出来：标题是标题、表格是表格、列表带项目符号。

要解决的问题仍然是**伪装**。老板键切过去之后，屏幕上那份东西得经得起看——一份摊着 `## 一、本季度进展` 的纯文本，和一份排版正常的文档，差别就在这里。

**范围：只作用于工作文档，且只作用于扩展名为 `.md` / `.markdown` 的那一路。** 小说（导入过滤器只收 txt）与 `.txt` 工作文档一个字都不变。

## 2. 现状

工作文档已经是「第二本 `Novel`」，由 `loadNovelFromFile` 读进来：解码 → 归一化换行 → `splitChapters` → `flatText`。阅读区显示的是 `flatText.slice(revealStart, cursor)` 这一个**字符串**（`Page.tsx` 的 `visibleText`）。

两件顺带确认的事：

- **小说那条路不可能出现 md。** `wt:import-novel` 的过滤器只有 `txt` 与「所有文件」，而「所有文件」是给无扩展名/异扩展名的**纯文本**留的口子，不是给 md 的入口。真正要防的是有人在小说那一路手动选一个 `.md`——那种情况下本功能**不生效**（判定按路径扩展名，而小说那一路不走渲染分支），显示的是原文。这与今天的行为一致。
- **md 工作文档的章节列表基本只有一章。** `splitChapters` 认的是「第 X 章」那类中文章节标记，`# 标题` 不在其列。老板模式下章节栏本来就是收起的（见老板键设计第 7 节），所以看不见；这里只是说明它不会因此坏掉。

## 3. 四条核心决策

这四条是「选了这条，别的都跟着变」的。每条都对应访谈里的一次拍板。

### 3.1 解析成带字符偏移的语法树，按偏移裁剪

用 `remark`（mdast）解析整份文档。mdast 的每个节点自带 `position.start.offset` / `end.offset`，就是**相对 `flatText` 的字符下标**——和 `cursor`、`revealStart` 是同一个坐标系，不需要任何换算。

于是「按字符揭示」这条既有机制直接变成「按偏移裁剪」：光标走到哪，哪些节点的文本被填上，是一个纯函数。

**为什么不把「已经抽出来的那一段」当独立 md 重新解析**（那样实现最省）：未闭合的记号会退化成字面文字，半截表格根本不成表格。它与下面 3.2 直接冲突，所以第一条就被否掉了。

### 3.2 结构预知

**一个块只要开始被揭示（它的起始偏移 < cursor），它的完整结构就画出来；还没开始的块一概不画。**

表格的表头一露头，整张网格就画全，后面几行是空的、随抽字被填上——看起来像「正在填表」。代价是提前泄露「后面还有几行」这类**结构**信息。这是明确接受的：屏幕上永远不出现任何**未揭示的字符**，只出现空骨架。

这条规则同时给了「后面还有多少」一个界：只有已经开始、且没被折走的块在屏幕上，不会在只有一页正文时先铺出十页空骨架。

**「块」的定义要钉死：mdast 根节点的直接子节点（顶层块）。** 整份文档里所有「块」的判断——保留还是丢掉、量高度、铺满切点、折叠切点——一律在这一层做。表格的行、列表的项**不是**块：它们是块的内部结构，一旦所在的块被保留，它们整体跟着保留（这正是上面那张表能整张画出来的原因）。

**两类叶子要分开判，这一条是实施时量出来才看得见的。**

- `image`、`footnoteReference`、`break` 这类**没有文字**的叶子：起始偏移 < cursor 就整体出现。从中间「切」对它们没有意义，所以「一揭示就整体出现」是自洽的（图片那条口径见 8.3）。
- **内嵌 HTML 是例外：按「抽完才出现」判（`end <= cursor`）。** 原因是它的 `value` 里**连标签里的文字一起**——块级的 `<div>后面的话</div>` 在整个语法树里是**一个**节点。从中间切只会得到 `<di` 这种碎片（`tokenizeHtml` 认不出它是标签，会当普通文字吐出来，等于把裸源码字符弄上屏），不切就等于把未揭示的字一起放上屏。两条都不可接受，所以只有「等它抽完」这一条路。

  行内 HTML 的**文字泄露**问题不存在（remark 会把 `前文 <span>后面</span>` 切成 text / html / text / html 四个节点，文字本来就在 text 节点里、照常被截），**但这条规则对两类 html 节点一视同仁**：切开的 `<spa` 碎片同样会被当普通文字吐出来，所以行内的 `<span>` 也等它整个抽完才出现。这个分叉不值得按行内/块级判——一个空的 `<span></span>` 渲不渲染在屏幕上看不出差别，而分叉要多一次解析。

### 3.3 渲染只发生在渲染层，core 不动

本模块**不被 main 共享**，而 `src/core/` 的定义是「被 main 与 renderer 共享的纯逻辑」。另外整个 remark 生态都是 ESM-only（实测 `remark@15.0.1` 与 `remark-gfm@4.0.1` 的 `"type"` 都是 `module`；`remark-parse` 同族），放进 core 等于让 main 那份 `tsconfig.node.json` 也去解析它——多一类失败面，换不来任何东西。渲染层已经有 `src/renderer/src/state/shortcuts.ts` 这种纯模块的先例。

`src/core/bossKey.ts` 因此**基本不动**：它从「唯一的路」降级成「兜底的路」，见第 7 节。

### 3.4 屏幕上一辈子见不到裸记号

`**季度` 你抽到「季度」两个字时，它们**直接就是粗的**——解析器早就知道这一段是粗体。`#`、`**`、`|`、`>` 一个都不会作为字形出现。

这是 3.1 + 3.2 的直接推论：既然结构是预知的，记号就没有「先露出来再吃掉」的理由。要解决「记号看起来怪」，这一条是主刀。

## 4. 语法表（渲染到哪一档）

用户选的是**全套 CommonMark + GFM**。逐项落到渲染：

| 语法 | 渲染成 |
|---|---|
| 标题 1–6 | Word 内置「标题 1/2/3…」的样子，字号递减，深蓝加粗 |
| 粗体 / 斜体 / 删除线 | 对应的字形与颜色 |
| 行内代码 | 等宽 + 浅灰底 |
| 代码块（含语言标注） | 浅灰底 + 等宽 + 内边距；**不做语法高亮** |
| 无序 / 有序列表 | Word 的项目符号与编号，带缩进；嵌套照常 |
| 任务列表 `- [x]` | **不可点**的方框（文档运行期只读、永不修改，见既有硬规则） |
| 引用块 | 左侧竖线 + 灰色文字，可嵌套 |
| 分隔线 | 一条细横线 |
| 链接 | 像链接（蓝 + 下划线），**点了不做事**（见 9.3） |
| 表格（GFM） | 细网格线，宽度固定为正文宽、单元格自动换行，**不出现横向滚动条** |
| 图片 | 真的显示出来，见第 8 节 |
| 脚注 | 上标数字 + 文末列表，见 9.1 |
| 内嵌 HTML | 只渲染安全的排版标签，见第 11 节 |

**不做语法高亮**是刻意的：一份「Word 文档」里的代码块本来就是一块等宽字，加了配色反而更像编辑器、更不像文档。

## 5. 渲染管线

```
flatText ──remark-parse + remark-gfm──▶ mdast（带 position.offset）
                                          │  解析一次，按文档缓存
                                          ▼
                              clip(mdast, revealStart, cursor)
                                          │  每次渲染都跑，纯函数
                                          ▼
                         mdast-util-to-hast ──▶ hast
                                          ▼
                              rehype-sanitize（白名单）
                                          ▼
                              rehype-react ──▶ React 元素
```

**解析只做一次。** 200KB 的 md 解析是几十毫秒量级，每次按键重解析不可接受。缓存挂在 `App` 里，键是工作文档那个 `Novel` 对象——它一旦变（重新导入、移除）缓存自然失效。

裁剪之后的那一段很小（大约一页），所以后面几步每次渲染重跑是可以接受的。

**全仓不出现 `dangerouslySetInnerHTML`。** 内嵌 HTML 那一路也走「解析成节点 → 映射成 React 元素」，不把字符串塞进 DOM。这条是硬规矩，不是风格偏好。

## 6. 模块边界

**新增（全在渲染层）：**

| 文件 | 职责 | 依赖 |
|---|---|---|
| `src/renderer/src/markdown/parse.ts` | md 文本 → mdast。**全仓唯一 import remark 的地方** | `remark-parse` / `remark-gfm` |
| `src/renderer/src/markdown/clip.ts` | `(mdast, revealStart, cursor) → mdast`。纯函数 | 只有 `import type` |
| `src/renderer/src/markdown/fill.ts` | `(块高表, 目标高度) → 字符偏移`。纯函数 | 无 |
| `src/renderer/src/markdown/toReact.tsx` | clipped mdast → React 元素（管线后半段） | `mdast-util-to-hast` / `rehype-sanitize` / `rehype-react` |

**类型不另造一套。** `import type { Root } from 'mdast'` 是编译期擦除的，`@types/mdast` 只是个 devDependency，运行时零成本。这样 `clip.ts` 既是纯函数，又不用维护一套平行的节点类型。

**「什么该显示」只有 `clip.ts` 一处决定。** 它上面那层只管把拿到的树画出来，不做任何「这个该不该显示」的判断。这条边界是刻意的：它是唯一能被单测逐字钉死的部分，也是唯一会随口径变化的部分。

| 文件 | 改什么 |

## 7. 铺满的语义变更

老板键的「铺满一页」现在按**字符数**算：`CHARS_PER_SHEET = 1330` 是拿纯文本推的（626px 宽 ≈ 41.7 字/行 × 32 行）。渲染之后这个数不准了——记号被吃掉不显示、标题字号更大、列表有缩进、表格有边框，同样 1330 字占的高度差很多。再叠上 3.2 的结构预知（表格表头一露头整张网格就画出来），偏差会更大。

**新口径：按渲染后的真实高度铺，且停在块边界。**

```
1. 目标高度 = bossFillPercent% × 纸张正文区高度
             （从 .wt-page 的计算样式量出来，不写死 912）
2. 离屏渲染整份文档，量每个顶层块的 offsetHeight
   （量到目标高度的 2 倍就停，不必量完几十页）
3. pickFillCut(块高表, 目标高度) → 字符偏移（纯函数）
4. engine.revealTo(切点)
```

「停在块边界」的意思是：切点落在某个块的结束偏移上，**不切行、不切表格、不切引用块**。屏幕底部因此永远是一整块，不会出现半句话或半张空表格。

**`bossFillPercent` 的含义从「一页字符数的百分比」变成「一页高度的百分比」。** 100% 仍然是「刚好一页」，只是这个「一页」从估的变成量的。

**两条兜底，都必须有：**

1. **第一个块就超过一页** → 铺满那一个块。宁可溢出一页，也不能铺出一张白纸。
2. **量不出高度**（jsdom 里 `offsetHeight` 恒为 0，或测量抛错）→ **退回按字符数**，用的还是 `CHARS_PER_SHEET` / `fillCharsFor` 那一套。

所以 `src/core/bossKey.ts` 的逻辑**原样保留**，只是从「唯一的路」降级成「兜底的路」。两个好处：core 那批逐字节围栏与单测基本不用动；这条降级路径在 jsdom 里是**可测的**，否则「量高度」整块就是零覆盖（`tests/` 跑的是 jsdom，没有布局）。

**块高表的生命周期：** 进入老板模式时量一次；`⌘⇧↑` / `⌘⇧↓` 只重算切点，不重量（文档没变，块高也不变，变的只是目标高度）。重新导入或移除工作文档时丢弃。

## 8. 图片

### 8.1 两条来源，一条通道

渲染层是沙箱（`sandbox: true`），读不到磁盘、也不该自己联网。两种图片都经**同一条 IPC** 由主进程取回来，交给渲染层的都是 `data:` URL：

| 来源 | 主进程怎么做 |
|---|---|
| 本地路径 | 按工作文档所在目录解析相对路径，读文件 |
| `http:` / `https:` | 主进程去取 |

**基准目录由主进程自己算**，不接受渲染层传进来的路径：主进程从设置里读 `workDocPath`，取它的 `dirname`。这样渲染层能请求的东西被限定在「工作文档相邻的位置 + 网络」，而不是「任意基准目录」。

**CSP 一个字不改。** `img-src 'self' data:` 本来就允许 `data:`，所以这条通道走完，CSP 完全不用碰——这也正是选「主进程代取」而不是「放开 CSP」的理由（那个 meta 上面挂着一段警告注释，位置是承重的）。

### 8.2 抓取时机

**只抓已经抽出来的那张。** 图片节点被揭示（起始偏移 < cursor）的那一刻才请求，文档里没被抽到的外链一次也不会被访问。

### 8.3 出现时机

**一揭示就整张出现**（用户拍板）：不等 `](路径)` 抽完，路径还没抽完时图就跳出来。这与 3.2 是同一条规则——已经开始的东西，画完整的。

### 8.4 上限与失败

- 只接受 `image/*`，**超过 8MB 的拒绝**；网络请求 10 秒超时
- 失败（路径不存在、超时、不是图片、超限）→ 渲染层显示**占位框 + 替代文字**，不弹错、不打断
- 渲染层按「解析后的绝对来源」缓存拿到的 data URL，避免每帧重发 IPC

## 9. 三处具体的渲染口径

### 9.1 脚注

`[^1]` 显示成**上标数字**，全文的脚注定义收在正文末尾、一个「脚注」小标题下的列表里。

**不照 Word 的页面底脚注**：那需要「页面底部」这个概念，而本应用的纸是一张**连续变长的长纸**（`min-height: 1080px`，内容多了就长高），没有页面边界可言。硬造一个出来要额外的布局机制，收益只是更像 Word 一点点。

### 9.2 表格

宽度固定为正文宽（626px），单元格里的字自动换行，**不出现横向滚动条**——真 Word 也不横滚。列多的表会被压窄，这是接受的结果。

### 9.3 链接

样式像链接（蓝色 + 下划线），**点了不做事**。点开链接会拉起系统浏览器——一个伪装成 Word 的应用突然开浏览器，副作用太显眼，收益又接近于零（工作文档里的链接多半是内网地址或文档引用，本来也打不开）。

## 10. 样式

Word 风，逐项对齐 Word 内置样式：

- **标题**：微软雅黑 / 等线加粗，标题 1 用 Word 默认的深蓝 `#2F5496`，2/3 级依次减小字号、同一色系
- **正文**：继承现有 `.wt-page` 的字体（Georgia / 宋体系）
- **列表**：Word 的项目符号（`•`）与编号，缩进对齐
- **引用**：左侧 3px 竖线 + 灰色文字
- **代码块**：浅灰底 + 等宽 + 内边距；行内代码同色系、更小的内边距
- **表格**：细网格线（Word 的「网格型」），表头加粗
- **分隔线**：一条 `1px` 细横线

**所有颜色走 CSS 变量**，深色主题与「深色下纸张也变暗」两个开关都要跟着走——本仓库在这个坑上栽过（`color-scheme` 与主题变量是两套东西，滚动条与原生控件归前者管）。标题那个深蓝在深色下必须给一个亮一档的替身，否则在暗底上几乎看不见。

## 11. 安全边界

用户选的是「只渲染安全的排版标签」。具体口径：

- **白名单标签**：`br` `b` `strong` `i` `em` `u` `s` `del` `sub` `sup` `span` `div` `p` `code` `pre` `small` `mark` `hr`
- **属性一律丢弃**，包括 `style` / `class` / `id` / 一切 `on*`。丢 `style` 是刻意的：留着它等于让文档控制页面的外观，而外观是这个应用用来伪装的东西
- **白名单之外的标签**：标签本身丢掉，**里面的文字按普通文字保留**（`<script>alert(1)</script>` 显示成 `alert(1)`）。它永远不会被执行，因为整条路都不碰 `innerHTML`
- 整条渲染路径**不出现 `dangerouslySetInnerHTML`**（第 5 节）

**这条白名单挡住的是一条真实的链**：工作文档里的 HTML 若能带事件属性执行，它就在一个握着 `window.api` 的渲染进程里跑——而 `window.api` 上有导入小说、写设置、以及第 8 节那条读本地图片的通道。挡住执行面，「读文件」那条通道的暴露面就降回「图片能被读出来」这一档。

## 12. 错误处理与边界

| 情形 | 行为 |
|---|---|
| md 解析抛错 | 退化成**现有的纯文本路径**（同一个 `visibleText` 渲染），`console.warn` 一行。**不许白屏** |
| `.md` 里其实全是普通文字 | 正常——渲染出来就是一串普通段落，与今天肉眼看不出差别 |
| 图片读不出 / 超时 / 不是图片 / 超限 | 占位框 + 替代文字（8.4） |
| 量不出块高 | 退回按字符数（第 7 节兜底 2） |
| 第一个块就超过一页 | 铺满那一个块（第 7 节兜底 1） |
| 文档很大 | 解析一次并缓存；测量只量到目标高度的 2 倍 |
| 折叠条（`RENDER_WINDOW_LIMIT = 30000`） | md 这边按**块边界**切：从末尾往前累加各块的**字符长度**，到 30000 为止，取那个块的起始偏移作为折点。**不复用 `pickFillCut`**——那个函数吃的是高度，折叠这一步没有（也不该有）布局信息 |

## 13. 对既有代码与文档的改写

1. **核心不变量要改写。** `CLAUDE.md` 现在写的是「阅读区显示的内容恒等于 `flatText.slice(revealStart, cursor)`」。渲染之后 `#`、`**`、`|` 是字符但不当字形显示，所以要改成：

   > 阅读区**显示出来的文字**，等于已揭示那一段（`flatText.slice(revealStart, cursor)`）**去掉语法记号之后**的文字；此外不显示任何未揭示的字符。只有已经开始（起始偏移 < cursor）的块才画结构骨架，骨架里不含未揭示的字符。

   **小说那条路与 `.txt` 工作文档一个字不变**，改写只落在 `.md` 那一路。`CLAUDE.md` 里那句要写清这个分叉，否则下一个读它的人会以为不变量整体失效了。

2. **`src/core/bossKey.ts` 的注释**：`bossFillPercent` 的含义从「一页字符数」变成「一页高度」，`CHARS_PER_SHEET` / `fillCharsFor` 变成兜底。改的是注释，逻辑不动。

3. **实现计划的逐字节围栏**：本仓库的硬约定——动了源码（含只改注释）就要把 `docs/superpowers/plans/` 里对应的围栏同步回写，口径是 `md5(围栏原始内容) == md5(文件)`。本功能会动 `App.tsx` / `Page.tsx` / `bossKey.ts` / `ipc.ts` / `channels.ts` / `preload` / `global.d.ts`，这些都在 06 那份正本里有整文件围栏。

4. **新依赖**：`unified`、`remark-parse`、`remark-gfm`、`mdast-util-to-hast`、`rehype-sanitize`、`rehype-react`，以及 devDependency `@types/mdast`。全部是 ESM-only，**只允许渲染层引用**（`unified` 是用来把前两个串起来的那个壳，`remark` 元包本身不需要）。

## 14. 测试策略

jsdom 能判的：

| 层 | 测什么 |
|---|---|
| `parse.ts` | md → 树；白名单 HTML 的保留与丢弃；偏移值正确 |
| `clip.ts` | **逐字钉死**：未开始的块被丢掉；已开始块的结构保留而文本置空；跨越光标的文本被截断；`revealStart` 之前的块被丢掉 |
| `fill.ts` | 给定块高表与目标高度 → 切点落在块边界上；第一个块超高时的兜底；空文档 |
| `toReact.tsx` | 各语法的 DOM 结构（不做像素断言）；`<script>` 不产生脚本节点 |
| `App` 集成 | 导入 `.md` → 按老板键 → 页面是渲染后的结构；量高度失败时退回字符数；`.txt` 工作文档与小说**没变** |

**真机才能判的**（交给用户跑，列在实现计划末尾）：

- 老板模式下 md 的**实际观感**：标题字号、表格、代码块在真纸上好不好看
- **「铺满一页」是不是真的满页**——这条是 jsdom 量不出来的那一步，也是本功能最容易做歪的地方
- **深色主题下**标题那个深蓝、代码块底色是否还看得清
- 中文输入法在渲染后的正文里照常（老板模式下的抽字没变，但页面结构变了）
- 网络图片的加载与失败表现；本地图片的相对路径
